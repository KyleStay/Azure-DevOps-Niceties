# Reviewer test instructions

This document is a test procedure, not a claim that the tests have already passed. Paste the relevant procedure into the dashboard's private **Test instructions** field and add the publisher's real test access details there.

## Access the publisher must provide privately

- A test Azure DevOps organization and project URL.
- A dedicated test account, password or other supported login instructions, and any required access steps.
- A sample work-item URL with known ID, title, and type; preferably a Product Backlog Item.
- A sample parent and child relation, such as Feature 900 “Search improvements” → PBI 1234 “Improve search”. Use actual accessible IDs instead of these examples.
- Where to find a board, backlog, query result, and pull request with linked work items and a release’s stage Work items view in that project, so all claimed surfaces can be checked.

Keep credentials out of public documents. Provide a reviewer account with sample data and no access to sensitive production projects. The extension does not create an Azure DevOps account or bypass Azure DevOps permissions.

## Essential procedure

1. Install the extension, sign in to the provided Azure DevOps test project, and open the provided work item or board. The extension runs on `https://dev.azure.com/*` and organization-specific `https://*.visualstudio.com/*` addresses.
2. Open the extension's toolbar menu and verify **Enable enhanced copying** and **Enable selection summary** start on when no preference is saved. Turn copying off, reload, and verify the saved opt-out and Azure DevOps's native copy action, then turn copying back on. The copy preference is local to this device; parent-context and branch-prefix settings may sync. With **Sync theme with system** set to its initial **Automatic** choice, verify that the standard light/default theme follows system appearance, while a selected dark or high-contrast theme stays unchanged even when system appearance differs. Then choose **On** in the extension menu. Put the operating system in light mode. Azure DevOps should use its native light theme. Switch the operating system to dark mode with the Azure DevOps page still open: it should change to its native dark theme. Switch back and navigate within Azure DevOps; it should continue following system appearance. Check an editor/form as well as the surrounding shell. The extension applies the current page's theme without saving a new account preference. Choose **Off** for **Sync theme with system** in the extension menu: changing system appearance should now leave the current page theme in place. Reload and verify that the opt-out persists, then choose **On** and check that the current system appearance is applied. Native high-contrast themes and forced-colors settings should be preserved.
3. Hover the sample work item and click its existing work-item copy control. Paste into a rich-text editor: the whole label, such as `PBI 1234: Improve search`, should be linked to the work item. Paste into a plain-text editor: its readable label should remain. Expect one trimmed line with no leading/trailing whitespace, blank paragraphs, or font styling, including when the source title contains line breaks. Verify the pasted link inherits the destination font.
4. Repeat the same control with Shift held and paste into a plain-text editor: expect a Markdown link. Hold Alt (Option on Mac): expect `#1234`. Hold Ctrl (Command on Mac): expect the URL. Hold Shift+Alt (Shift+Option on Mac): expect `feature/1234-improve-search`, using the actual test item's ID and title.
5. Focus/select or hover the sample work item, then use `Shift+Alt+C` and `Shift+Alt+B`: expect the rich linked title and branch name. Focus an editable title/text field and type or use the same keys: the extension should leave that field's editing behavior alone.
6. Open the extension's toolbar menu. Enable **Include parent context**, then repeat rich and Markdown copy on the child item. Expect the linked parent before the child, separated by `›`. Change the branch prefix to `bugfix`, then copy a branch name: expect the new prefix. Close/reopen the menu and verify settings persist.
7. Disable **Include parent context** and copy again: expect only the child. A missing or inaccessible parent should also allow the child reference to copy. A slow parent lookup should time out after the extension's 3-second total lookup budget and still copy the child. Turn **Enable enhanced copying** off and confirm subsequent copy actions return to Azure DevOps behavior, then enable it again for remaining checks.
8. Repeat basic copy on the board, backlog, query result, work-item form, and a pull request's linked work-item list. An unrelated copy control, such as a Git branch name or field value, must retain its normal behavior. When a work item cannot be identified confidently, the extension leaves that native control alone.

9. Open the provided release → stage → Work items view. When copying is disabled, review the visible Enable copying card and approve it. Check that the first column contains labelled copy icons, the second contains row checkboxes with a select-all checkbox in its header, and State comes before Title. Type should be hidden and the list should fit narrow panels without horizontal scrolling. Open More copy options and check Copy all bugs + PBIs and Copy all PBIs; these should copy only matching loaded rows without changing selection. Repeat with Agile, Basic, CMMI, and custom category names; if project categories cannot load, manual type selection must remain available. Open Select by type to choose Bug and PBI while leaving Task unchecked. Copy the selection, paste only the chosen types, and check the Effort summary for selected loaded rows. Check partial type selection by toggling an individual row, type selection by keyboard, standard long/abbreviated names, and custom types. Uncheck a type while its selected rows are unloaded and confirm their references are removed. Copy all loaded must still include all types. Test the header select-all checkbox, Clear selection, Space on a checkbox, Ctrl/Command+C on the extension selection controls, and Shift+Alt+C inside the list. Native copy handlers and editable text fields elsewhere must keep working. Click an individual Copy button, and use Open on a linkless row. Copy all loaded (N) should copy one linked reference per visible loaded item in display order. Verify mixed types: Product Backlog Item → PBI, User Story → US, Test Case → TC. Repeat click modifiers for Markdown, IDs, URLs and branch names. Duplicate items count once. Temporarily unloaded selections remain copyable while the same list is open; closing/replacing the list or changing views clears them. Collapse/reopen the same mounted list, recycle a row, clear selection, and turn copying off; controls and selected references should be cleaned up appropriately.
10. Before changing the summary switch, select rows in a query or backlog containing displayed Effort, Story Points, and Size columns. Verify count and each estimate total separately, including zero and missing estimates, counts by type/state, and unassigned count. Change selection, edit displayed values, collapse/expand the panel, clear selection, and disable the feature. Summaries should work by default even when copying is off. Disable the summary switch, reload and verify the saved opt-out, then re-enable it. Totals cover only selected loaded rows and must not silently treat missing estimates as zero.

11. Check release work items, Sprints → Backlog, and product backlog individually, including reopening a collapsed panel and navigating between them. In tables, ARIA grids, legacy grids, and cards showing a State, click the state and verify the picker follows the item’s actual workflow, including custom types. Opening, cancelling, and arrow-key navigation must not save. Choosing a different state should send one revision-checked save and update duplicate displayed references. Test required fields, permission denial, concurrent revisions, and network errors: no failed or unconfirmed save may automatically retry. Recycled or removed rows must never cause a save to a different item. Existing native state editors and rows with unsaved inputs should remain untouched. Turning off inline state editing must remove its controls independently of copying and summaries. Use a controlled fixture for write testing; do not alter production work items for QA.

Clipboard actions require the page to be active and the copy gesture/shortcut to be performed by the reviewer. Pasting into a plain-text editor will not show rich HTML links; use a rich-text editor for that check.

## Implementation notes for reviewers

The package is Manifest V3 with no background service or analytics. `src/work-item.js` formats references, `src/content.js` enhances recognized copy gestures and optionally fetches Azure DevOps JSON parent data, and the options page saves parent-context, branch-prefix, and system-theme-sync preferences through `chrome.storage.sync`, plus the enhanced-copying, selection-summary, and inline-state-editing switches through `chrome.storage.local`. `src/state-client.js` reads workflow metadata and sends revision-checked state updates after an explicit choice; `src/state-editor.js` binds this to identifiable displayed state fields. Enhanced copying starts enabled unless the user saves a local opt-out. Selection summaries default on and process displayed selected rows unless their separate local switch is turned off. Theme matching defaults to Automatic: standard light/default themes follow system appearance, selected dark/high-contrast themes are preserved, and saved On/Off choices override this behavior.

`src/theme.js` is packaged with the extension and runs in the page's MAIN world. It uses Azure DevOps's own synchronous or AMD module loader to access `VSS/Platform/Context`, obtains `IVssThemeService`, loads the site's available-themes data provider if required, and applies a known native light/dark theme ID. Azure DevOps's loader may load its own native module from Microsoft. The extension does not fetch JavaScript for evaluation or download replacement extension logic. This integration is explicitly disclosed for remote-code review; it is not a claim of a policy exemption or prior store approval.

The `clipboardWrite` permission writes a reference after a user gesture. `storage` preserves preferences, which may sync through Google. Site matching is limited to the Azure DevOps cloud domains above. The extension does not read clipboard contents or Chrome's browsing-history database.


For compact State controls, verify there is no persistent dropdown arrow or reserved indicator width. Hover the text or focus it with the keyboard to see the interaction cue; hover must not move the label or adjacent columns. Open the picker on a middle workflow state and confirm it remains in workflow order with the current state selected in place. When no explicit order metadata exists, choices retain the server's state-definition order. Only valid available transitions should remain selectable.


After an inline State save, open the same item in its native form. On hosts exposing WorkItemFormService, a matching older form without unsaved edits should refresh automatically. Edit a separate title field before a second inline save and confirm the native form and unsaved title remain untouched. Resolve that edit yourself and verify the form refreshes if still older. Check opt-out, opening a different item, and unsupported native APIs; the extension must not save fields or reload the page. If the native service is unavailable, verify the form's own Refresh command still loads the saved State.


For release layout, check full-width table and toolbar use through nested unnamed containers. Headers may be outside a separate presentation table: there must be only one toolbar and aligned Copy, selection, State, and Title cells. IDs and Type stay hidden, and copied references retain IDs. Check long titles and native state labels in nested narrow wrappers, with no horizontal scrollbar. The closed toolbar should occupy one short row at normal widths and wrap compactly on narrow screens. More copy options and Select by type open dismissible menus; check Escape, clicking outside, keyboard navigation, and unchanged copy modifiers. Turn copying off to verify native widths and wrappers are restored.

For native Bolt release rows, inspect leading/trailing presentation cells: they must take no layout width, and ID must map to its real column before being hidden. Check the work-item-small-view/title-link flex chain with long titles. An empty native title link should gain a readable extension-owned link after a read-only missing-title lookup. Verify copied text includes the recovered title, the native anchor is unchanged, and a native title appearing later takes over. Recycle a row to another ID and check its title/State association. Permission failures should leave an Open link and disable incomplete copying. A title literally equal to Done must stay intact while toggling State editing. Turn copying off during a lookup and verify cancellation, cleared cache, and restored native DOM.
